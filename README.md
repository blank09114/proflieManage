# proflieManage

의뢰인 한 명이 자작 캐릭터의 프로필과 이미지 피드를 관리하는 웹사이트다. 방문자는 메인 화면에서 콘텐츠를 열람하고, 관리자는 로그인 후 수정 화면에서 내용을 편집한다.

## 현재 상태

`react-migration` 브랜치에서 기존 HTML·CSS·JavaScript 화면과 기본 동작을 React·TypeScript로 이식했다.

- `/`에서 메인 화면, `/edit`에서 수정 화면을 확인한다. 기존 `/manage.html` 주소도 수정 화면으로 연결한다.
- 모달·피드 열기와 닫기, 클릭한 이미지 확대, 색상 미리보기, 파일명 표시, 피드와 섹션 추가·삭제, 공통 입력 검증을 React 상태와 이벤트로 처리한다.
- 선택한 이미지의 `File` 객체는 수정 화면의 편집 상태에 보관한다.
- 로그인은 비밀번호 공란 검사, 저장은 검증 후 임시 알림 단계다. `/edit`은 현재 이식 확인용으로 직접 접근할 수 있다.
- 다음 작업은 Supabase 데이터·Storage·권한 구성과 실제 인증·조회·저장 연결이다.

이식 후 빌드·린트와 브라우저 동작 검증 67개를 통과했다. 390·768·1280px 화면과 긴 파일명 표시도 확인했다.

퍼블리싱 원본과 상세 작업 계획은 작업 공간에서 프로젝트 루트의 형제 폴더인 `sketch/`와 `sketch/plan.md`에 둔다.

## 개발 실행

```cmd

npm run dev
```

## 원격 저장소

- `origin`은 기본 저장소다. [원본 저장소](https://github.com/3rd-hargreaves/proflieManage)
- `backup`은 백업 저장소다. [백업 저장소](https://github.com/blank09114/proflieManage)

로컬 Git 저장소에 `origin`과 `backup` 원격을 등록했다. 작업 브랜치를 각 원격에 별도로 푸시한다.

## 브랜치 전략

1. `main`에 직접 커밋하거나 푸시하지 않는다.
2. 기능명이 드러나는 작업 브랜치를 만든다. 브랜치명 예시는 `react-migration`, `admin-auth`, `feed-sort`다.
3. 코드와 문서를 작업 브랜치에서 수정하고 커밋한 뒤 해당 브랜치를 원격으로 푸시한다.
4. 작업 브랜치에서 `main`을 대상으로 PR을 생성한다.
5. 변경사항과 필요한 검증 결과를 확인하고 PR을 통해 `main`에 병합한다.
6. 다음 작업은 최신 `main`을 기준으로 새 브랜치를 만들어 시작한다.

`backup`에도 같은 규칙을 적용한다. 백업할 작업 브랜치를 별도로 푸시하고 `main` 반영은 PR을 통해 진행한다.

이 문서의 작업 규칙과 GitHub 브랜치 보호 설정은 별도로 관리한다. 보호 설정의 적용 여부는 저장소에서 확인한다.

## 구현 방향

- 메인 `/`와 수정 `/edit` 두 페이지로 구성한다.
- 관리자 이메일은 고정하고 비밀번호만 입력받아 Supabase Auth로 로그인한다.
- 프로필·섹션·키워드·피드 순서·테마는 Supabase DB에서 관리한다.
- 이미지는 Supabase Storage의 `profile/`, `feed/` 경로에 저장한다.
- 섹션 서식, 이미지 확대·스와이프, 섹션과 피드의 드래그 정렬을 구현한다.
- 테마색은 CSS 변수에 적용하고 메인 페이지 제목은 캐릭터 이름과 연동한다.
- 프런트엔드는 Vercel에 배포한다.
