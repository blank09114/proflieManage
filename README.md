# proflieManage

의뢰인 한 명이 자작 캐릭터의 프로필과 이미지 피드를 관리하는 웹사이트다. 방문자는 메인 화면에서 콘텐츠를 열람하고, 관리자는 로그인 후 수정 화면에서 내용을 편집한다.

## 현재 상태

`react-migration` 브랜치에서 기존 HTML·CSS·JavaScript 화면과 기본 동작을 React·TypeScript로 이식했다.

- `/`에서 메인 화면, `/edit`에서 수정 화면을 확인한다. 기존 `/manage.html` 주소도 수정 화면으로 연결한다.
- 모달·피드 열기와 닫기, 클릭한 이미지 확대, 색상 미리보기, 파일명 표시, 피드와 섹션 추가·삭제, 공통 입력 검증을 React 상태와 이벤트로 처리한다.
- 선택한 이미지의 `File` 객체는 수정 화면의 편집 상태에 보관한다.
- Supabase 클라이언트와 고정 이메일 로그인, 관리자 UUID 확인, 세션 복원·변경 감지, 로그아웃을 연결했다. `/edit`과 `/manage.html`은 확인된 관리자만 접근할 수 있다.
- 메인 화면은 DB의 프로필·섹션·키워드·피드·테마를 조회한다. 목록은 저장된 순서로 표시하고, 캐릭터 이름을 페이지 제목에, 테마색을 CSS 변수에 적용한다.
- 로딩·조회 오류·재시도·빈 목록과 이미지 표시 실패를 처리한다.
- `site-edit-saving` 브랜치에서 수정 화면의 DB 데이터 채우기와 전체 저장, 프로필·피드 이미지 업로드·교체·삭제를 연결했다. 테마 편집값도 CSS 변수에 미리 적용한다.
- 저장 중 중복 요청을 차단하고, 실패하면 편집 내용을 유지한다. 다른 창에서 먼저 저장한 내용과 충돌하면 최신 데이터를 다시 불러올 수 있다.

이식 후 빌드·린트와 브라우저 동작 검증 67개를 통과했다. 390·768·1280px 화면과 긴 파일명 표시도 확인했다.

Supabase 연결 코드는 실제 SDK와 로컬 인증 테스트 서버로 브라우저 검증 19개를 통과했다. 실제 프로젝트의 환경변수를 입력하고 5개 테이블·초기값·RLS를 적용했으며, 공개 키로 5개 테이블의 API 조회를 확인했다.

메인 데이터 연결은 실제 프로젝트의 초기 데이터 표시와 테스트 데이터를 이용한 브라우저 검증 40개를 통과했다. 정렬·테마·페이지 제목·이미지 경로·빈 목록·조회 실패와 재시도, 대량 목록의 페이지 단위 조회를 확인했다.

수정·저장 연결은 브라우저 검증 33개와 저장 서비스 모킹 11개를 통과했다. 실제 Supabase에 저장 함수·Storage 정책을 적용했고, 롤백 검증으로 관리자 권한·ID 유지·순서 교환·추가/삭제·재시도·충돌·전체 롤백을 확인했다. 390·768·1280px 레이아웃과 빌드·린트도 통과했다. 이미지 업로드·삭제 HTTP 흐름은 테스트 서버에서 확인했다.

퍼블리싱 원본과 상세 작업 계획은 작업 공간에서 프로젝트 루트의 형제 폴더인 `sketch/`와 `sketch/plan.md`에 둔다.

## 개발 실행

프로젝트 루트에서 실행한다.

```cmd
cd /d C:\WS\ProfileWS\proflieManage
npm install
npm run dev
```

## Supabase 환경변수

프로젝트 루트의 `.env.local`에 값을 입력한다. 같은 항목을 `.env.example`에도 정리했다.

| 환경변수 | 확인 위치 |
|---|---|
| `VITE_SUPABASE_URL` | 프로젝트의 Connect 창에서 Project URL 복사 |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Project Settings → API Keys → Publishable key 복사 |
| `VITE_ADMIN_EMAIL` | 관리자 Auth 계정 이메일. `dkal1572@naver.com`으로 설정 |
| `VITE_ADMIN_USER_ID` | Authentication → Users에서 관리자 계정의 User UID 복사 |
| `VITE_SUPABASE_STORAGE_BUCKET` | 이미지용 공개 버킷 이름. 기본값은 `site-images` |

URL과 공개 키는 프로젝트의 Connect 창에서도 함께 확인할 수 있다. [Supabase 연결 안내](https://supabase.com/docs/guides/getting-started/api-keys)

`VITE_ADMIN_USER_ID`는 `supabase/schema.sql`의 `private.is_site_admin()`에 지정한 UUID와 동일하게 설정한다. 관리자 이메일·비밀번호는 Supabase Auth 사용자로 설정하고, 사이트에서는 비밀번호만 입력한다.

브라우저용 키는 Publishable key 또는 기존 프로젝트의 `anon` 키를 사용한다. Secret key와 `service_role` 키는 서버 전용이다. `.env.local`은 Git에서 제외한다. [Supabase API 키 안내](https://supabase.com/docs/guides/getting-started/api-keys)

환경변수를 저장한 뒤 개발 서버를 재시작한다. Vercel 배포 시에는 같은 환경변수를 프로젝트 설정에 입력하고 다시 배포한다.

## 공개 이미지 조회

프로필과 피드의 이미지 경로는 공개 버킷 `site-images` 안의 `profile/…`, `feed/…` 경로로 저장한다. 이 버킷을 실제 프로젝트에 생성했으며 `supabase/schema.sql`에도 생성 구문을 포함했다. 메인 화면은 DB 경로를 Storage 공개 URL로 변환해 표시한다.

현재 DB에는 프로필·테마 초기값만 있고 섹션·키워드·피드 목록은 비어 있다. 이미지 파일과 목록을 등록하면 해당 콘텐츠가 메인에 표시된다.

## 수정 내용 저장

새 프로젝트에서는 `supabase/schema.sql`을 실행한 뒤 `supabase/save.sql`을 실행한다. 저장 SQL에는 관리자 전용 `save_site` 함수와 `site-images` 버킷의 `profile/`, `feed/` 접근 정책이 포함된다. 다른 버킷을 사용하면 환경변수와 Storage 정책의 버킷 이름을 함께 변경한다.

수정 화면은 기존 데이터와 이미지 경로를 읽는다. 새로 선택한 이미지만 고유한 경로에 업로드하고, 프로필·테마·섹션·키워드·피드의 내용과 순서를 한 번의 DB 트랜잭션으로 저장한다. 유지한 항목의 ID와 기존 이미지 경로는 보존한다. DB 반영이 성공하면 교체되거나 삭제된 기존 이미지를 정리한다.

업로드 단계에서 실패하면 DB를 변경하지 않고 미저장 파일을 정리한다. DB 요청의 응답을 받지 못하면 성공 여부가 불명확하므로 새 이미지를 보존한다. 같은 화면에서 다시 저장하면 업로드한 경로를 재사용하며, 이미 반영된 동일 요청은 중복 항목을 만들지 않는다. 결과가 불명확한 상태에서 편집을 버리거나 화면을 닫으면 미사용 업로드 파일이 남을 수 있다.

기존 이미지 정리만 실패한 경우에는 내용 저장 성공과 정리 재시도를 구분해 표시한다. 정리 대기 목록과 업로드 재사용 정보는 현재 화면의 메모리에 보관한다.

## 원격 저장소

- `origin`은 기본 저장소다. [원본 저장소](https://github.com/3rd-hargreaves/proflieManage)
- `backup`은 백업 저장소다. [백업 저장소](https://github.com/blank09114/proflieManage)

로컬 Git 저장소에 `origin`과 `backup` 원격을 등록했다. 작업 브랜치를 각 원격에 별도로 푸시한다.

## 브랜치 전략

1. `main`에 직접 커밋하거나 푸시하지 않는다.
2. 기능명이 드러나는 작업 브랜치를 만든다. 브랜치명 예시는 `react-migration`, `admin-auth`, `feed-sort`다.
3. 코드와 문서를 작업 브랜치에서 수정하고 커밋한 뒤 해당 브랜치를 원격으로 푸시한다.
4. 작업 브랜치에서 `main`을 대상으로 PR을 생성한다.
5. 변경사항과 필요한 검증 결과를 확인하고 PR을 통해 `main`에 병합한다.
6. 다음 작업은 최신 `main`을 기준으로 새 브랜치를 만들어 시작한다.

`backup`에도 같은 규칙을 적용한다. 백업할 작업 브랜치를 별도로 푸시하고 `main` 반영은 PR을 통해 진행한다.

이 문서의 작업 규칙과 GitHub 브랜치 보호 설정은 별도로 관리한다. 보호 설정의 적용 여부는 저장소에서 확인한다.

## 구현 방향

- 메인 `/`와 수정 `/edit` 두 페이지로 구성한다.
- 관리자 이메일은 고정하고 비밀번호만 입력받아 Supabase Auth로 로그인한다.
- 프로필·섹션·키워드·피드 순서·테마는 Supabase DB에서 관리한다.
- 이미지는 Supabase Storage의 `profile/`, `feed/` 경로에 저장한다.
- 섹션 서식, 이미지 확대·스와이프, 섹션과 피드의 드래그 정렬을 구현한다.
- 테마색은 CSS 변수에 적용하고 메인 페이지 제목은 캐릭터 이름과 연동한다.
- 프런트엔드는 Vercel에 배포한다.
